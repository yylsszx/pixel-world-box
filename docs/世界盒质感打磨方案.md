# 像素世界盒子 · WorldBox 质感打磨总体方案

- 版本：v1（2026-11-15）
- 基线：worklog #92，v0.82-preview，远端 c1d7afb 之后
- 性质：总路线图 + 各打磨轮（#93 起）的任务书。每轮仍走既有节奏：开工先 fetch 比对远端 → 实施 → QA → worklog 条目 → push-web.sh；每攒约 3 笔合并升位一次。
- 研究基础：superworldbox.com 官网与官方 changelog 实测抓取（2026-11-15）、Steam 商店页官方特性表、The Official Worldbox Wiki（Fandom）、r/Worldbox 社区讨论，以及本仓库全量代码审计（行号级证据见第 2 节）。

---

## 0. 一页结论

诊断三句话：

1. **机制深度已经不输甚至局部超过 WorldBox**（50 项科技/六纪元、五态军团与世界大战动态参战、102 件七槽装备、200 个神力工具、板块构造与深时侵蚀、神谕外脑），但**深度不可见**——v0.76 以来的九线深化全部用 1~3px 的细节表达（矿灯、浮台尖顶、军旗士气条），默认视野下玩家根本看不到，所以体感是"机制粗糙、没有深度"。
2. **美术的硬伤是像素密度与表达体系，不是没有艺术能力**：人形常规档总高 6px、绵羊 2×1px、狼 3×1px、Boss 巨龙约 5×3px；全库只有一种树；没有任何描边；默认 zoom 4.5 恰好落在"动物降级为双色矩形"的 LOD 档。这是工程问题，可以按计划修。
3. **WorldBox 的质感是一条公式**：小而完整的像素表达体系（每生物有轮廓/剪影/动画、每群系专属植被、水面逐格波光、统一像素 UI） × 微型叙事（每个生物有名字/特质/装备/家谱，点开就是故事） × 反馈密度（每次交互有声音、动画、粒子回应）。我们三项都卡在"表达层"，不在"模拟层"。

策略一句话：**不推倒机制**。三条主线推进——美术重制（M1→M5）、机制可见性工程（M6 上）、特质系统补齐（M6 下）；先地基（调色板 + 精灵缓存 + LOD 政策），后批量重制；每轮可验收、可截图对比、可回滚。

### 1.4 社区对美术风格的共识

- r/Worldbox 原话："It looks great. That style could be defined as **minimalist and kawaii pixel art**."（极简可爱系像素画）
- 游戏实况可稳定观察到的美术特征（作为定性基准，不虚构具体像素数）：
  - 每个单位有 1px 深色**轮廓线**与可辨识剪影，行走有摆动动画，有上下左右**四向朝向**；
  - 每个群系有**专属植被**（草原橡树、雪原松树、沙漠棕榈/仙人掌、焦土枯木等），植被随风摇曳；
  - 水面有**逐格波光动画**；昼夜循环 + 夜间灯火；
  - 地图上有王国**旗帜与名牌**；UI 是统一像素风（图标优先、文字极简）；
  - 任意缩放级别看到的都是**同一套完整像素画**（缩放不降级为色块）。

### 1.5 WorldBox 质感公式

> 质感 = 视觉可读性（3 秒读懂屏幕上发生的事） × 微型叙事（每个生物点开有故事） × 反馈密度（每次交互有回应）

WorldBox 模拟层的复杂度其实低于我们（无 50 项科技树、无世界大战阵营机制、无神谕 AI），但表达层三项全部满分。**这就是差距的全部真相。**

## 2. 代码级现状审计（行号级证据）

### 2.1 美术根因清单

| # | 根因 | 代码证据 | 与 WorldBox 对比 |
|---|---|---|---|
| A1 | **生物像素密度不足** | 人形常规档总高 6px（sprites.ts:590）；绵羊 2×1px、狼 3×1px、巨龙约 5×3px（sprites.ts:1348-1417） | 每单位有完整轮廓、肢体、装备剪影 |
| A2 | **默认视野是"色块档"** | LOD 中档 2.5≤zoom<5.6 用 ANIMAL_LOD 双色矩形（render.ts:2138-2168、2223-2241），默认 zoom=4.5 正落此档 | 任意缩放都是完整像素画 |
| A3 | **无轮廓线、无死亡动画、只有左右镜像** | 全库无 outline 概念；死亡瞬变骨堆 decal（render.ts:1467-1495）；朝向仅 u.flip | 1px 描边 + 倒地/消散帧 + 四向 |
| A4 | **精绘档只覆盖 6/45 精灵目标** | QUAD_FINE 仅 wolf/snowwolf/sheep/bear/deer + drawPersonFine（render.ts:2170-2173）；龙/九头蛇/克拉肯等 Boss 永远是简笔 | 招牌巨兽都是精心绘制的大精灵 |
| A5 | **只有一种树、无群系植被、无风摆** | drawTree 单函数（sprites.ts:3927-4007）；沙漠/雪原无植被 prop；树静态烘焙（engine.ts:17584-17586），windAt 风场未接入 | 每群系专属树 + 摇曳 |
| A6 | **地形平涂感** | 12 色基础表 + ±6 明度抖动 + 棋盘混合（constants.ts:42-67、engine.ts:17317-17347）；无草须边缘、悬崖立面、路缘石 | 边缘有装饰、悬崖有立面、tile 有手工味 |
| A7 | **水体静态烘焙** | 浪花/波光全靠稀疏粒子（render.ts:214-407） | 逐格波浪帧动画 |
| A8 | **UI 视觉语言割裂** | shadcn 玻璃拟态 + lucide 矢量图标 + 8×8 PIX 像素图标混排 + 中文密集面板 | 统一像素风 UI |
| A9 | **无主调色板** | sprites.ts 内联十六进制色值数千处（"金色"至少有 #ffd93d/#f5c842/#ffd700/#c9a02a 四种）；Unity 侧再手工镜像一遍（WbRender.cs:25-36） | 有限色板纪律 |
| A10 | **架构制约美术上限** | 每单位每帧 30~40 次 fillRect 即时绘制 + 动态层每帧全量重绘；任何加描边/加帧都会线性放大 CPU 成本 | 预渲染精灵 + 缩放绘制 |

**A10 是所有美术升级的前置依赖：不先做精灵缓存，一切"加细"都是性能负债。**

## 3. 总体策略与三条铁律

**铁律 1（先地基后上层）**：M1 调色板 → 精灵缓存 → LOD 政策必须先行。描边、加倍尺寸、加帧动画都会放大每单位每帧的绘制成本；没有缓存层，加细 = 掉帧。

**铁律 2（每轮可验收）**：沿用打磨轮节奏。每个美术轮必须交付：改动前后同场景截图对比（scripts/shot-sample.mjs 管线）+ 帧预算测量（budget EMA 对比）+ 必要时 vlm-check 主观评估。禁止"顺手多改"造成轮次不可回滚。

**铁律 3（单源双写）**：美术数据 TS 单源。Unity 迁移当前暂停（2026-11-07，worklog:5038），但恢复时必须走既有 gen-* 黄金链（先扩黄金场景再改实现），禁止手抄色值到 C#。调色板模块建成后，Unity 侧 WbRenderTables 改由 palette 表机械镜像。

## 4. 分阶段实施计划（M1→M6）

> 轮次预算按现有"半天到一天一轮"的节奏估；#93 起编号。每阶段末有"出关条件"，不满足不进下一阶段。

### M1 质感地基（#93~#94，2 轮）

**目标**：让"加细"不再付出性能代价，并立刻消灭"默认视野是色块"这个最大体感问题。

| 轮 | 内容 | 关键改动 |
|---|---|---|
| #93 速赢包 | ① 新建 `src/lib/game/palette.ts` 主调色板模块（约 40 色核心板：描边 K、肤/发族、叶族×四季、木族、金族、血族、火族×3、地形 12 色+水深 5 色收编为命名常量；王国 12 色沿用）；② **按需精灵缓存**：以 (species, frame, flip, sizeClass, paletteKey) 为 key 把 draw* 光栅到小离屏 canvas，LRU 上限约 2048 槽（平均 24×24，约 11MB），渲染分发处 drawImage 替代即时 fillRect 序列——draw 函数本体不动，黄金链不受影响；③ **LOD 政策重划**：zoom<1.5 保留色点档，1.5≤zoom<8 全部走完整精灵（缓存缩小绘制），≥8 精绘档——**废除默认视野的 ANIMAL_LOD 色块**；④ 绵羊/狼两个最寒酸物种先重制为 8×6/10×8 并加 1px 描边（给用户立刻可见的变化） | palette.ts 新文件；render.ts LOD 表与分发；sprites.ts 两个函数 |
| #94 缓存全覆盖 | 精灵缓存 key 扩展覆盖全部 44 物种 + 人形（含装备组合哈希进 key）；性能基线建立：2400 单位满载跑 budget EMA，记录 M1 前后对比进 worklog；eslint 增加裸 hex 检查规则（新代码禁止 sprites/render 之外的十六进制色值字面量） | render.ts 缓分发；eslint.config.mjs |

**出关条件**：默认 zoom 4.5 下无任何双色块动物；2400 单位满载 budget EMA 不劣于 M1 前 ±5%；黄金全绿。

### M2 生物重制（#95~#99，5 轮）

**目标**：45 个精灵目标全部达到"有轮廓、有剪影、有 2 帧步态、有死亡帧"的 WorldBox 基准线；招牌 Boss 获得大尺寸精绘。

**统一精灵规范（所有物种）**：
- 描边：统一 1px 深色轮廓 `#1a1613`（palette 命名 K）；
- 体积：小型动物 8×6 起、中型 10×8、大型 12×10、人形 8×10、Boss 24~48 宽（人形从 6px 提到 10px，密度 ×1.7）；
- 双色调身体（基色 + 暗面）+ 1px 高光；受击红闪与挤压回弹保留；
- 步态 2 帧（现存 2 帧机制沿用，帧内容重画）；死亡 3 帧（倒地→消散→粒子）+ 现存血迹 decal；
- 朝向：本轮维持左右镜像（四向列入长线池，见第 5 节）；
- 特质视觉钩子：巨型/侏儒缩放已有，补 blessed 微光、infected 色偏、veteran 伤疤点。

**人形常规档设计稿示例（8 宽 × 10 高，K=描边，S=肤，H=发，T=衣，A=甲，B=靴，W=武器）**：

**出关条件**：五个群系（草原/雪原/沙漠/沼泽/焦土）同框截图植被一眼可辨；水面动画肉眼可见且帧预算不超；悬崖/山脊在 zoom 4.5 下有立体感。

## 5. 风险与依赖

| 风险 | 缓解 |
|---|---|
| 精灵缓存内存增长 | LRU 上限 + 槽位尺寸监控进 PerfHud；M1 建立基线后每轮对照 |

| 黄金链协议 | 缓存只包分发层不动 draw 函数本体，黄金录制不受影响；凡改 draw 本体（M2 全部轮次）先扩黄金场景再改——沿用 Unity 铁律的 TS 版 |
| Unity 恢复迁移时的追赶成本 | 美术轮集中批量重跑 gen-*（每 M 阶段末一次，而不是每轮） |
| 视觉主观性（越改越花） | 每轮截图对比 + vlm-check 评估 + 用户抽查；palette 是唯一合法色源，防色彩膨胀 |
| 性能回归 | budget EMA 每轮记录；M2 起任何一轮回归 >5% 必须当轮修复 |
